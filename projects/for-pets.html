1. 프로젝트 소개

5인 팀으로 반려동물 보호자와 펫시터를 연결하는 예약 중개 플랫폼을 개발했습니다. 백엔드에서 펫시터 예약·결제 흐름과 Gemini, RAG, SSE 기반 AI 시터 추천 챗봇 및 리뷰 요약 기능을 담당했습니다.

결제가 끝난 뒤 정산 상태를 쉽게 확인할 수 있도록 책임을 나눴고, LLM 응답이 늦거나 실패해도 예약·결제 기능은 계속 사용할 수 있게 처리했습니다.

2. 담당 역할

예약·결제

예약 생성 이후 결제 요청, 승인, 상태 변경과 취소까지 이어지는 흐름을 구현했습니다.

정산

결제 완료 이후 펫시터 지급 금액과 정산 상태를 별도 책임으로 분리했습니다.

AI 추천

Gemini Embedding과 Qdrant를 연동한 리뷰 근거 기반 시터 추천 기능을 구현했습니다.

대화 경험

Redis에 최근 5턴의 대화 세션을 저장하고 SSE로 응답을 스트리밍했습니다.

3. 기술 스택

BackendJava 21 · Spring Boot · Spring Data JPA · Spring Security
DataMySQL · Redis · Qdrant
AI & RealtimeSpring AI · Gemini API · Gemini Embedding · RAG · SSE
Payment & MonitoringPortOne · Micrometer

4. 주요 기능

예약·결제·정산

예약부터 PG 결제 승인·취소, 펫시터 지급 상태까지 단계별로 추적합니다.

리뷰 기반 검색

리뷰 원문을 벡터화하고 자연어 질문과 의미가 유사한 리뷰를 추천 근거로 제공합니다.

멀티턴 대화

Redis에 최근 5턴을 저장해 사용자의 후속 질문 맥락을 유지합니다.

스트리밍 응답

SSE로 생성 중인 답변을 나누어 전달해 긴 응답의 대기 경험을 개선합니다.

5. 문제를 해결한 과정

예약·결제·정산 책임 분리

문제가 된 부분

예약 이후 승인·취소·정산이 한 흐름에 얽히면 거래 상태와 지급 누락 지점을 추적하기 어렵습니다.

해결한 방법

결제는 승인·취소·실패 처리를, 정산은 지급 금액과 정산 상태를 맡도록 책임을 나눴습니다.

확인한 결과

결제와 정산 상태를 단계별로 확인할 수 있어 지급이 누락된 지점을 찾기 쉬워졌습니다.

리뷰 근거 기반 RAG 추천

문제가 된 부분

키워드 검색만으로는 보호자의 자연어 조건과 리뷰의 실제 의미를 연결하기 어려웠습니다.

해결한 방법

Gemini Embedding으로 리뷰를 벡터화하고 Qdrant 검색 결과를 답변 근거로 사용했습니다.

확인한 결과

자연어로 조건을 물어보면 관련 리뷰를 근거로 시터를 찾을 수 있게 됐습니다.

외부 LLM 장애 격리

문제가 된 부분

LLM 응답 지연이나 오류가 예약·결제 기능까지 느리게 만들 수 있었습니다.

해결한 방법

connect timeout 2초, read timeout 5초, 요청 제한과 fallback 응답을 적용했습니다.

확인한 방법

Micrometer로 응답 시간·오류 수·토큰 사용량을 수집해 기준을 점검했습니다.

6. 결과 및 회고

최근 5턴

Redis 세션으로 후속 질문의 대화 맥락을 유지했습니다.

3종 지표

LLM 응답 시간·오류 수·토큰 사용량을 수집했습니다.

2초 / 5초

connect·read timeout을 분리해 장애 대응 기준을 명시했습니다.

이 작업을 하면서 AI 답변의 품질만큼 외부 API가 실패했을 때의 처리도 중요하다는 것을 알게 됐습니다. 예약·결제·정산을 나누니 문제가 생긴 단계와 지급 누락 여부도 훨씬 쉽게 확인할 수 있었습니다.
