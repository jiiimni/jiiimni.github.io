1. 프로젝트 소개

5인 팀으로 PortOne 기반 일반 결제·정기 결제 시스템을 구현했습니다. 구독 도메인과 주문 도메인을 담당하며 구독 플랜 변경·해지 로직, 주문 시점 상품 정보 스냅샷 저장과 구독 서비스 단위 테스트를 맡았습니다.

무료 플랜 전환이나 즉시 해지가 필요한 경우에는 바로 반영되도록 구독 조건을 나눴습니다. 상품 정보가 바뀌어도 과거 주문 내역에는 결제 당시 정보가 남도록 저장 방식도 수정했습니다.

2. 담당 역할

구독 플랜 변경

플랜과 구독 상태에 따라 예약 변경과 즉시 변경을 구분했습니다.

구독 해지

다음 결제일 해지와 즉시 해지가 필요한 케이스를 분리했습니다.

주문 스냅샷

OrderItem에 주문 당시 상품명과 가격을 저장했습니다.

단위 테스트

구독 생성·변경·해지·재구독 상태 전이를 테스트로 검증했습니다.

3. 기술 스택

BackendJava · Spring Boot · Spring Data JPA
DataMySQL · JPA Entity State Transition
PaymentPortOne · General Payment · Recurring Payment
TestJUnit5 · Mockito

4. 주요 기능

일반 결제

주문을 생성하고 PortOne을 통해 결제하는 흐름을 제공합니다.

정기 결제

구독 플랜과 결제 주기에 따라 정기 결제 상태를 관리합니다.

구독 관리

플랜 변경, 해지와 재구독에 따른 상태 전이를 처리합니다.

주문 내역

결제 당시의 상품명과 금액을 유지해 과거 주문을 정확히 보여줍니다.

5. 문제를 해결한 과정

예약 반영과 즉시 반영 분리

문제가 된 부분

모든 플랜 변경·해지가 다음 결제일까지 대기해 무료 전환과 즉시 해지도 늦게 반영됐습니다.

해결한 방법

구독 상태와 플랜 종류에 따라 예약 변경과 즉시 변경·해지를 나눴습니다.

확인한 결과

즉시 해지가 필요한 사용자는 다음 결제일까지 기다리지 않아도 됩니다.

주문 시점 상품 정보 스냅샷

문제가 된 부분

주문 후 상품명이나 가격이 바뀌면 과거 주문 내역까지 현재 정보로 보일 수 있었습니다.

해결한 방법

OrderItem에 productName과 productPrice를 주문 생성 시점 값으로 저장했습니다.

확인한 결과

상품 정보가 바뀌어도 주문 내역에는 결제 당시 상품명과 가격이 남습니다.

구독 상태 전이 회귀 테스트

문제가 된 부분

상태와 플랜 조합이 늘수록 한쪽의 변경이 다른 구독 흐름을 깨뜨릴 수 있었습니다.

확인한 방법

생성·플랜 변경·해지·재구독을 각각 단위 테스트로 작성했습니다.

확인한 결과

약 15개의 테스트로 주요 상태 전이가 예상대로 동작하는지 확인했습니다.

6. 결과 및 회고

약 15건

구독 생성·변경·해지·재구독 단위 테스트를 작성했습니다.

주문 시점 보존

상품 변경 이후에도 과거 주문의 상품명과 결제 금액을 유지했습니다.

구독을 구현하면서 활성·비활성 두 값만으로는 플랜 변경과 해지 시점을 표현하기 어렵다는 것을 알게 됐습니다. 주문 내역도 현재 상품 정보만 바라보게 하면 과거 기록이 달라질 수 있어, 결제 당시의 상품명과 가격을 따로 남겼습니다.
